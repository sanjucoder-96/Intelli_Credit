# ADR-0014: Frontend: Next.js 15 + TanStack Query + openapi-typescript client + SSE + single ECharts viz library

**Status:** Accepted · **Date:** 2026-07-16 · **Phase:** 1 (Architecture)

## Context

The frontend is where the platform's core claims are judged. Bank-grade explainability is a UI problem as much as a data problem: an analyst must hover a citation in a CAM and land on the exact page and bounding box of a GSTR-3B or CIBIL Commercial report; a credit officer must review HITL forms rendered from typed `ReviewRequest` schemas; a judge must watch a live run timeline stream agent steps, confidence components, and per-run cost in real time. All of this must be built and maintained by one developer, run inside docker-compose on a Windows 11 laptop, and survive a 10-minute live demo without a flaky connection or a mid-demo re-render bug.

Two architectural invariants from [ARCHITECTURE.md](../ARCHITECTURE.md) constrain the choice. First, **the frontend never changes per workflow** (§4): dashboards are server-driven from `GET /workflows/{id}/manifest` over a fixed block vocabulary (`risk_gauge`, `table`, `timeline`, `heatmap`, `network`, `narrative`, `evidence_chain`). The rendering layer must therefore cover a wide visual range — gauges, heatmaps, timelines, force-directed promoter/entity networks — behind one consistent API and one theming system, or workflow #13 quietly becomes a frontend fork. Second, live progress is strictly server→client: the worker publishes compact events to Redis pub/sub, the API relays them, and the browser's only upstream message during a run is a plain POST (start run, submit HITL review, ask chat). The transport should match that shape exactly.

Finally, the FE/BE contract problem is acute for a solo developer: twelve agent output schemas, a Report IR, manifest block descriptors, and HITL form schemas all evolve during the build. Hand-maintained TypeScript types drift silently and the drift surfaces as demo-day rendering bugs. The backend already emits an OpenAPI document for free (FastAPI); the frontend should consume it mechanically.

## Decision

- **Framework:** Next.js 15 (App Router) + TypeScript (`strict`), built as `output: "standalone"` for a slim Docker image (the `frontend` compose service).
  - Styling: **Tailwind CSS** with **shadcn/ui** — vendored, ownable components (forms, tables, dialogs) that carry the credit-officer review portal and HITL form rendering.
  - **Framer Motion** for page/stage transitions and run-progress choreography: agent timeline steps animating through pending → running → done/degraded, matched to SSE events.
  - Dark mode via **next-themes** (class strategy), which also drives chart theming (below).
- **Server state: TanStack Query v5** over a client generated by **openapi-typescript** (with `openapi-fetch` as the thin typed runtime).
  - The client is regenerated from the FastAPI-exported OpenAPI document by a `make generate-client` step; **CI regenerates and type-checks**, so any backend schema change that would break the UI fails the build instead of the demo.
  - No hand-written request/response types anywhere; query keys wrap the generated paths.
  - Client state is deliberately minimal: TanStack Query owns all server data; residual UI state (viewer zoom, panel layout) is React state/context. No Redux/Zustand global store until a concrete need survives review.
- **Streaming: SSE via native `EventSource`.** `GET /runs/{id}/events` and the chat token stream are FastAPI `StreamingResponse` relays over Redis pub/sub (`run:{id}:events`).
  - Events carry monotonic per-run ids; Redis pub/sub is live fan-out only (it holds no backlog); reconnects send `Last-Event-ID` (the last delivered AgentStep seq) and the API rehydrates the gap from the Postgres trace endpoint before resuming live relay — a dropped connection mid-demo resumes losslessly.
  - Auth uses a short-lived, single-purpose stream ticket issued by the API: native `EventSource` cannot set an `Authorization` header, and the JWT must never sit in a long-lived URL.
- **One visualization library: Apache ECharts** via `echarts-for-react`, with per-chart modular imports (`echarts/core` + only the used renderers/charts) to contain bundle size.
  - ECharts alone covers the entire manifest block vocabulary: bar/line financial charts, portfolio heatmaps, risk gauges (masterscale grade IC1–IC10 with score-breakdown drill-down), run/cashflow timelines, and force-directed promoter/entity network graphs for the fraud module's counterparty cycles.
  - Exactly **two registered ECharts themes** (light/dark), generated from the Tailwind design tokens in one module and switched by next-themes — every visual follows dark mode from a single definition.
- **Document viewer: pdf.js**, rendering page canvases with a citation-highlight overlay layer positioned from stored `Citation{page, bboxes[]}` rows (word-level for born-digital pages, line-level for RapidOCR'd scans), deep-linked as `?doc=…&page=…&highlight=…` — every claim in the report viewer and evidence-chain explorer is one click from its source pixel.
- **Server-driven dashboards:** a `BlockRenderer` maps each manifest block descriptor to a typed React component; six of the seven blocks render through ECharts or shadcn/ui primitives, and `evidence_chain` composes the AgentStep/Evidence trace replay. Adding workflow #13 ships zero frontend changes.

## Alternatives considered

### WebSockets / Socket.IO
Rejected because the traffic is one-directional. Run progress and chat tokens flow server→client; the only upstream messages (start run, HITL submission, chat prompt) are ordinary POSTs. WebSockets buy that non-need with real operating cost: connection upgrade handling through proxies, heartbeat/reconnect logic written by hand (or a Socket.IO dependency on both sides), and a second non-HTTP path to secure and debug. SSE is plain HTTP — it traverses the docker-compose network and any future reverse proxy untouched, reconnects natively, and `Last-Event-ID` gives resumability almost for free. The replay gateway (ARCHITECTURE.md §5) also benefits: recorded runs stream byte-identically through the very same SSE path used live, which is both the CI seam and the demo-day offline fallback.

### GraphQL / tRPC
Both solve problems this system does not have. GraphQL's value is client-shaped queries across many consumers; here there is exactly one first-party client, and the cost is a second schema language, resolver maintenance, and an N+1 discipline problem layered over SQLAlchemy. tRPC assumes a TypeScript backend — against FastAPI it degenerates into schema duplication, hand-mirroring Pydantic models in Zod. The OpenAPI document already exists as a FastAPI by-product; `openapi-typescript` turns it into compile-time contract enforcement with zero runtime and zero second schema. The contract-honesty goal is met by generation, not by a protocol migration.

### Raw fetch with hand-rolled types
The zero-dependency option, and the most expensive one. Hand-written interfaces for twelve agent output schemas, the Report IR, manifest blocks, and HITL form schemas *will* drift from Pydantic reality — silently, because TypeScript checks the hand-written fiction, not the wire truth. It also re-implements what TanStack Query provides (cache, invalidation, retries, polling idioms, request dedup) as ad-hoc `useEffect` code, historically the largest bug surface in solo-built React apps. Rejected on failure mode: contract drift discovered by a judge, not by CI.

### Recharts + Cytoscape.js + custom SVG gauges (multi-library charting)
The conventional stack: Recharts for bar/line, Cytoscape or react-force-graph for networks, a bespoke SVG gauge. That is three dependencies, three APIs, three theming systems to keep coherent across light/dark, and three sets of interaction/tooltip behaviors — the sprawl the judge panel explicitly flagged. The manifest block vocabulary makes this worse: server-driven dashboards demand uniform rendering, and mixing libraries means the "same" dashboard looks stitched together per block. ECharts covers every required visual, including the two hard ones (gauges and force-directed graphs), natively. `visx` was considered and rejected for the same reason — it still needs a separate graph-layout solution.

### Hand-rolled D3
Maximum control, minimum leverage. Weeks of solo-developer time on axes, scales, legends, and canvas performance — spent on visuals instead of the platform that is actually being judged. D3 remains available *inside* an escape hatch if a block someday exceeds ECharts (none of the seven does), but it is not the default.

## Consequences

**Positive**

- FE/BE contract drift is a compile error, not a runtime surprise — the twelve agent output schemas, Report IR, manifest blocks, and HITL form schemas all reach TypeScript mechanically.
- The frontend genuinely never changes per workflow: the extensibility promise of ARCHITECTURE.md §4 holds at the UI layer, which is where such promises usually die.
- One theme definition governs every chart, gauge, heatmap, and network graph in both light and dark modes; the demo looks like one product, not a component collage.
- SSE + the replay gateway make the live demo resumable after a dropped connection and runnable fully offline — recorded runs stream through the identical `EventSource` path.
- shadcn/ui components are vendored code the developer owns and can patch, not a versioned dependency to chase across breaking releases.

**Negative / accepted trade-offs**

- ECharts renders to canvas: DOM-level assertion on chart internals is unavailable, so chart unit tests assert on ECharts option objects and pixel coverage lives only in the Playwright demo-path smoke.
- ECharts is a large library; modular imports are mandatory discipline, backstopped by a CI bundle-size check rather than trust.
- Native `EventSource` cannot send headers, forcing the small bespoke stream-ticket mechanism (threat-modelled alongside [ADR-0013](ADR-0013-auth-and-tenancy.md)).
- Next.js App Router still evolves quickly; the major version is pinned and upgrades are taken deliberately, not automatically.
- TanStack Query's cache must be explicitly invalidated on SSE-driven state changes (run finished → refetch findings/report). This event-to-invalidation map is small and testable, but it is a real coupling between the streaming layer and the query layer that must be maintained as endpoints grow.

**Follow-up obligations**

- `make generate-client` plus CI regeneration/type-check lands with the project scaffold in Phase 2 — the contract gate must exist before the first endpoint is consumed.
- The SSE relay (monotonic event ids, Postgres trace-endpoint gap rehydration for `Last-Event-ID`, stream tickets) is built once with the first run timeline and reused unchanged for ingestion progress and chat tokens.
- The two ECharts themes are derived from Tailwind tokens in one module; per-chart color literals are banned in review, and the theme module is revisited at the block-vocabulary freeze after the third real workflow (ARCHITECTURE.md §4).
- One Playwright smoke over the exact demo path — upload → live run timeline → citation hover → deep-linked pdf.js highlight → report — is the standing merge gate for the frontend build phases.
- If a future manifest block genuinely exceeds ECharts, the remedy is a new block type with its own renderer — never a second general-purpose charting library.
